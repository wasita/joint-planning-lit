# HANDOFF — joint-planning-lit

_Snapshot taken 2026-08-12, before returning the lab laptop. Everything below describes state as of that date._

## What this is

A curated, annotated reading list of **123 papers on joint planning and multi-agent
coordination** — where computational cognitive science, behavioral game theory, and
multi-agent AI meet. Every paper carries a tier (read in full / skim / know it exists), a
thread assignment (A–H: behavioral game theory and focal points; virtual bargaining;
computational theory of mind and inverse planning; joint action and commitment;
resource-rational and hierarchical planning; multi-agent AI; continuous-time spatial
coordination; collective intelligence and social learning), an estimated reading time, and
a prose annotation arguing why it earns its place. A four-week plan (~4 hrs/week, dated for
1–28 September) picks 16 of them as a spine.

This is postdoc-direction scaffolding, not analysis — it is the onboarding runway for the
next position, built in a week (2026-08-03 to 2026-08-10) right after the July defense. It
is not connected to **`wavelength`** or **`wavelength-analysis`** as a codebase, but it is
where the theoretical follow-on lives: the level-k / cognitive-hierarchy and
inverse-planning threads here are the same literature that **`prag_net_memo`** implements,
and thread C overlaps directly with the listener-model direction sketched in
`wavelength-analysis/docs/`. The abandoned web-app plan in `PLAN.md` was going to be forked
from `svelte-interactive-expt-template`.

Three artifacts, one source of record:

- `data/papers.json` — the machine-readable source of record. 123 records, schemaVersion 1,
  version 1.3, updated 2026-08-10. Fields per paper: authors, year, title, venue, citation
  (raw + html), `why` annotation, tier, est_hours, links, flags, thread, week, doi, corpusId,
  abstract, tags, status.
- `vault/` — an Obsidian vault generated from that JSON: 123 notes in `vault/papers/` plus
  `Reading dashboard.md`, which uses Dataview queries to render this-week's-plan, unread
  tier-1, everything-by-thread, and a done-with-ratings table. Read state lives in each
  note's YAML frontmatter (`status`, `rating`, `started`, `finished`, `tags`).
- `index.html` (148 KB) — the public, publishable static site, generated by
  `scripts/build_site.py` from the same JSON.

## Open threads

- **September is the deadline this was built for.** The four-week plan is dated 1–28
  September and budgeted at ~4 hrs/week. `vault/private/open-items.md` is written as
  instructions to a future self starting then.
- **Every paper's `status` is still `to-read`.** No reading has been logged in the vault
  frontmatter. The dashboard's "done" table is empty.
- **Unverified citations, listed in `open-items.md`.** The most consequential one flagged

  author's own publications page and could not be found in the CogSci program or
  eScholarship — the note says to ask him directly. Several other entries have unconfirmed
  venues, author lists, or affiliations. A handful of CogSci 2026 items will resolve on their
  own once proceedings post.
- **Site vs data can fork.** `PLAN.md` §12 raises it explicitly: the extractor runs one way
  (guide → JSON), so hand-editing `reading-guide.html` after the extraction will diverge from
  `papers.json`. The intended resolution is that `papers.json` becomes authoritative and the
  guide becomes a generated export. That has not been implemented — `build_site.py` generates
  `index.html` from the JSON, but `reading-guide.html` is still a hand-maintained artifact.
- The README's own caveats, which the future reader should take seriously: annotations are
  editorial judgments, not consensus positions; and roughly half the list is CogSci
  proceedings with no DOI, which breaks anything that keys on one.

## Picking this up again

```bash
git clone https://github.com/wasita/joint-planning-lit.git
cd joint-planning-lit
```

Then copy the gitignored files listed above from the old machine (or from wherever this
snapshot ends up) into place: `PLAN.md`, `reading-guide.html`, `vault/private/`, and
`scripts/extract_papers.py` from `_to_delete/`.

As a reading environment:

1. Install [Obsidian](https://obsidian.md) (free).
2. **Open folder as vault** → point it at `vault/`.
3. Settings → Community plugins → Browse → install and enable **Dataview**. Without it the
   dashboard renders as raw code blocks.
4. Open `Reading dashboard.md`. Update state by editing frontmatter:
   `status: to-read | reading | skimmed | read`, `rating: 1-5`, `started:`, `finished:`,
   `tags:`. Tables update automatically. Notes go under `## Notes`; link papers with
   `[[Wikilinks]]` under `## Connections` and the graph view (⌘G) draws the network.

As data / to regenerate:

```bash
python3 scripts/make_vault.py data/papers.json vault/   # regenerate notes; SKIPS existing
python3 scripts/build_site.py data/papers.json index.html   # regenerate the public site
```

No dependencies beyond stdlib Python 3 — both scripts import only `json`, `html`, `os`, `re`,
`sys`, `collections`. There is no environment to set up, no lockfile, no venv.

First thing to check: `python3 scripts/build_site.py data/papers.json /tmp/test.html` and
confirm the output is close to the committed `index.html`. That tells you the JSON and the
generator are still in sync after all the 08-10 churn.

## Landmines

- **`make_vault.py` skips notes that already exist.** That is by design — it is what protects
  your reading notes from being clobbered on regeneration — but it also means edits to a
  paper's annotation in `papers.json` will *not* propagate to an existing vault note. If you
  need a note rebuilt, delete it first.
- **The gitignore is load-bearing for privacy, not just tidiness.** `reading-guide.html`,
  `PLAN.md`, and `vault/private/` are excluded because they name a specific lab and PIs,
  discuss hiring context, and speculate about funding. Before making this repo public (or if
  it already is), check that nothing you add reintroduces that content — including this
  HANDOFF file, which deliberately describes those files without quoting their contents.
  **Do not commit HANDOFF.md without rereading it with that in mind.**
- `_to_delete/` and `_stage/` are gitignored, so they exist only on this disk. They are
  disposable, but `rm -rf _to_delete` also destroys the only copy of `extract_papers.py`.
  Rescue it first.
- The `git-debris` directory documents an interrupted git write on this working copy. Nothing
  is currently broken, but do not treat this copy as authoritative — clone fresh from GitHub
  and layer the private files on top.
- The site build's prose lives partly *inside* `scripts/build_site.py` (thread lead-in
  paragraphs are Python string constants, not JSON fields). Editing thread framing means
  editing the script, not the data.
